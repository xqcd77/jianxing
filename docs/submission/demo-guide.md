# 简行答辩演示操作说明

建议用预先准备的本地合成账户演示，网络或模型额度异常时使用截图解释，不现场填写真实凭证。汇报正文控制在9分30秒左右，预留30秒切换页面。

## 演示准备

按部署说明启动服务，登录demo账户，使用演示工具模拟转入4500元。确认联系人、模型配置和可用余额。历史账户若有未完成任务，换新的合成数据目录准备，不删除需要保留的真实评测记录。

## 演示步骤

1. 输入“给妈妈转400元，给小王转1500元，剩余的钱的20%用于理财并比较”。说明系统应保留三个目标，研究预算为520元。
2. 展开转账卡片，核对收款人、金额、可用余额及授权要求。仅由本人点击确认或填写演示验证。
3. 查看研究报告的关键数字、产品条件与来源。说明用户选择产品不等于授权申购。
4. 修改一项尚未完成的金额，展示关联预算重算；已完成转账保留回执，不重复执行。
5. 打开历史会话、记忆和上下文容量入口，说明当前任务状态与历史偏好分别保存。

上述是操作脚本与预期，不代表交付时已经在评委账户执行。实际模型表述可能变化，以任务状态和回执为准。

## 常见答辩问题

为什么采用多Agent：账单、理财和办理需要不同证据与工具，Supervisor分派，独立核验补查；简单任务不必强行经过所有角色。

为什么同时使用ChromaDB和SQLite：前者检索相近文本，后者保存可回读原文与正式业务状态，向量结果不能充当账本。

如何防止重复付款：保留完成节点、授权指纹、幂等键和回执，未知提交先查询。

效果如何验证：离线规则测试检查状态与不变量，66题真实模型诊断同时检查语义，保留两项失败并说明测量边界。

能否接真实银行：当前不能直接接入。真实身份、适当性、清算、安全和合规需单独完成。
