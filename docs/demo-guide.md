# 最小演示闭环

## 资金分配与授权

1. 登录demo，使用演示工具模拟6000元工资到账。
2. 选择跨场景联动→资金分配，选择预算、转账和理财组合。
3. 填写生活费3000元、给妈妈800元、模拟现金产品500元。
4. 核对资金影响与DAG，确认黄色步骤。
5. 申购卡片获取演示验证码，再由本人验证并执行。
6. 回执成功后，余额4700元、预留3000元、可用1700元。

以上是模拟银行，不是真实银行扣款。演示验证码绑定用户、计划、节点、指纹与时限，仅限当次使用，不代表真实短信因子。

## 只读深度研究

从账单或理财进入深入研究，填写计划金额、新增生活/应急预留与用款日期。账单角色核查资金，理财角色核对条款，报告展示来源与排除原因。先检查报告期间余额没有因分析而减少；选择方案后才进入新的确认与强验证。

## 订阅与卡片

只停视频会员的银行代扣，检查商户合同仍有效；需要解约时另行选择商户合同范围。设置卡片支付限额和游戏类别限制，核对回执中的状态；挂失卡的解挂不得当作普通交易解锁。

## 展示截图

README的14张图使用独立数据目录、20000元合成入账及规则演示模式，通过实际银行API与浏览器操作生成。它们覆盖登录、工作台、执行步骤、多目标、强验证、风险测评、研究、账单、理财、卡片、订阅、资金依赖、ETF资料与手机端。ETF外部资料使用固定夹具，不代表实时行情；截图不代表业务大模型回答结果。[来源清单](assets/screenshots/capture-manifest.json)记录尺寸、状态与文件哈希。

重新截图时，使用新数据目录启动隔离服务，再显式设置BANK_UI_TEST_URL与输出目录，运行`scripts/capture_gallery.cjs`。脚本要求账户初始余额为0，会修改该演示账户的资金、订阅与卡片状态，不能指向已有个人数据目录。需要Playwright和Edge（或通过BANK_BROWSER_PATH指定Chromium）。

```powershell
# 终端1：使用从未运行过的新数据目录
.venv\Scripts\python.exe scripts/serve_upgrade_fixture.py --port 8141 --data-dir .data/gallery-fresh --research-delay 5

# 终端2：Playwright已安装在当前Node环境中
$env:BANK_UI_TEST_URL='http://127.0.0.1:8141'
$env:BANK_SCREENSHOT_DIR='.data/gallery-capture'
node scripts/capture_gallery.cjs
```

脚本仅截取真实页面及实际组件范围，不替换回复、金额、任务状态或回执。发布版本转为无损WebP，每个场景只保留一张文件；原始PNG留在被忽略的本地数据目录。登录和工作台为全景，业务细节为组件取景，手机图宽度限制为320px；功能配对采用双栏，研究报告单栏展示。
