# 简行：项目介绍

项目时间：2026.09—2026.10。以下两种表述对应同一银行沙箱原型，分别侧重产品设计与应用工程；功能和指标不表示真实银行接入或商业化上线。

## AI产品方向

**简行｜银行多智能体与深度研究助手**

针对手机银行入口分散、办理链路长及金融分析依据不足的问题，基于OpenAI Agents SDK、LangGraph与ChromaDB构建融合Multi-Agent与Deep Research的银行Agent原型，覆盖转账、账单分析、理财等6类场景、31项主菜单入口。

- **产品规划：** 围绕明确需求快速办理、复杂需求先分析再决策，设计“直接办理＋Deep Research”双路径，采用1个Supervisor＋4个子Agent，统筹账单研究、理财研究、业务办理与独立核验。将组合需求拆解为目标清单与DAG计划，明确办理顺序、所需条件及授权要求，支持独立任务分别推进、受阻任务补充条件后续办；将研究结果衔接至办理，形成“分析—选择—授权—回执”业务闭环。
- **上下文与共享记忆：** 针对重复填写、条件遗忘及中断后重新发起的问题，设计“任务状态＋共享记忆”分层机制，保存办理参数、进度与版本，结合ChromaDB构建“Embedding检索—TextRank提取—原始证据回读”链路。明确信息更新与访问权限规则，保留金额、收款人及否定要求；续办时核验条件变化、保留已完成回执，实现信息复用、任务接续与依据回查。
- **评测与迭代：** 建立“可交互原型规则检验＋10领域58题评测集＋LLM-as-Judge五维评分”体系，覆盖组合办理、多轮交互、深度研究及异常恢复。围绕任务遗漏、金额误解与跨轮遗忘定位并优化规划、核验与记忆链路；同题集、同业务模型及统一评分标准下，当前方案严格通过率93.10%、加权评分4.60/5，Single-Agent对照为70.69%、3.94/5。

## AI应用工程方向

**简行｜银行多智能体与深度研究系统**

基于FastAPI、OpenAI Agents SDK、LangGraph与ChromaDB构建融合Multi-Agent、Deep Research与DAG任务规划的银行智能体，在金融沙箱中覆盖转账、账单分析、理财等6类场景、31项主菜单入口。

- **多智能体编排与执行：** 针对组合需求遗漏、研究与办理脱节的问题，实现Supervisor＋4个子Agent架构，由LangGraph管理任务流转，统一Harness接入Agents SDK并控制调用预算。双研究Agent并行取证，通过结构化结论与证据引用完成“取证—核验—定向补查—汇总”；业务Agent生成DAG计划，结合依赖校验与按需独立核验支持分步办理，资金网关统一控制授权、实时预检与幂等执行。
- **上下文与共享记忆：** 通过持久化检查点与有界Verify—Backtrack—Replan保存进度、核验变化条件并重规划未完成步骤，保留已完成回执。采用Pydantic直传金额、收款人及否定约束，结合ChromaDB向量索引与SQLite原文存储，实现“Embedding检索—TextRank提取—原文回读”；通过用户、会话及角色过滤控制访问，以版本校验处理信息冲突，支持上下文压缩、跨轮续办与证据追溯。
- **评测流水线：** 自建BankFlowBench（10领域／58题），搭建“规则校验＋LLM-as-Judge五维评分”流水线，覆盖组合办理、多轮交互、深度研究及异常恢复，检查授权合规、资金守恒与全部必需任务项。同题集、同业务模型及统一评分标准下，当前方案严格通过率93.10%（54/58）、加权评分4.60/5，Single-Agent对照为70.69%（41/58）、3.94/5；保留失败与未决记录。

## 实现与指标口径

- **架构分工：** Agents SDK执行有界角色提案，LangGraph保存工作流与检查点，Harness管理预算、取消与事件，业务网关独占资金授权与执行。SDK名称不表示业务模型必须使用OpenAI模型，本轮评测业务模型为`deepseek-flash`。
- **记忆分工：** Chroma保存派生向量和权限元数据；SQLite保存任务、账本、来源、回执与原文。TextRank提取原句，必要时回读原文；历史记忆不替代实时银行事实和新交易授权。
- **范围：** 31项为当前主菜单入口，43条为包含展开子项的内部操作定义，不把分组和子项混作主菜单数量。六类业务服务为确定性规则组件，不额外计为六个LLM Agent。
- **最新测量：** 2026-10-25完整58题，各题一次；五维加权原值为4.5984与3.9350，按2∶2∶1∶1∶1加权。Single Agent有15题失败、2题未决，质量分使用57份有效裁判；未决留在58题分母、不计通过。
- **比较边界：** 两组模型调用上限分别为16次、10次，属于非等预算方案对照。题集已参与开发，不作为纯架构因果结论、未见任务泛化能力或生产可靠性证明；指标绑定冻结测量版本，不表示任意仓库提交的复测结果。
