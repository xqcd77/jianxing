# 第一批上下文改进：任务交接单与统一ContextBuilder

实施日期：2026-10-26。复用现有LangGraph、Harness、SQL任务状态与Chroma记忆服务，增加只读任务交接单和模型上下文装配；不新增长期记忆整理、Skill运行时或模型压缩服务。

## 调用链

```text
已认证入口
  → ContextBuilder读取本人当前会话的任务与实时银行事实
  → TaskBrief：所有目标、参数、版本、依赖、缺项、回执引用与下一步
  → 按目标并集选择能力，按领域选择必要facts与历史上下文
  → Harness在每次模型调用／协议修复前重新装配
  → 完整请求Token预算检查
  → Agents SDK／legacy_http执行一次结构化提案
  → 原DAG校验、整单资金预检、按需独立核验、用户授权与银行网关
  → 正式任务状态、账本与回执更新
```

`TaskBrief`是模型输入的派生视图，不是第二份业务状态。没有新增存储交接单的SQL表、Document或Chroma记录；后续调用从正式状态重新生成。没有因为生成交接单增加模型调用。

## 状态来源与字段

入口在`PlannerAgent.context_builder`，所有应用模型复用的Harness绑定同一Builder。意图理解入口和Supervisor路由也使用Builder读取上下文；确定性短路径继续由原规则处理。

| 交接单内容 | 来源与规则 |
| --- | --- |
| 计划、目标与版本 | 本人同会话的goal_agenda、Plan和Node；节点当前参数与状态优先于旧目标副本 |
| 完成与禁止重放 | closed_goal_ids列出原任务终态；明确新发起的另一笔业务仍是新目标，须重新授权 |
| 回执引用 | 必须同时匹配本人、业务操作与具体节点的幂等键；引用错误时核实原结果，不重放资金步骤 |
| 缺项 | 由已有操作参数定义计算，保留已经提供的金额、对象、日期和依赖 |
| 条件变化 | 计划版本变化后，旧公开资料预算与待补银行任务标为NEEDS_RECHECK |
| 研究进度 | 按本人同会话的正式research文档读取状态，不直接沿用旧agenda中的运行中标记 |
| 否定要求 | 保留本轮明确约束及计划已保存的保护要求；历史文字不提供授权 |
| 下一步 | 对UNKNOWN核实原提交，对缺项只补缺项，对待确认步骤等待认证授权 |

生成的dialogue／memory文档中即使包含`active_plan`、`task_brief`等同名字段，也不能成为正式任务状态；这些派生字段从受权限约束的来源重建。

## 上下文按需装配

- 规划／业务角色：接收所有目标的交接单、必要当前facts、当前计划、待补草案及相关历史记忆。工具目录取所有未完成目标与本轮需求涉及领域的并集，保留所需前置能力。
- 路由角色：使用新读取的任务状态，原payload中旧计划与旧待补请求不能覆盖它。
- 研究／核验角色：保留图提供的原始需求、领域证据与候选结果，不再额外注入其他角色的历史上下文；交接单只提供任务信息，不包含角色私有推理。
- 历史处理：保留近期对话和较早的关键用户条件，省略更早的助手长说明；正式节点结果在模型上下文中保留回执引用，完整内容仍可从原来源读取。
- 资金事实：单纯转账不注入完整产品目录；涉及理财、卡片等多目标时保留对应领域事实。完整原始请求、业务Schema及必要证据不由Builder随意截断，超限仍由原预算机制阻断。

`context.prepared`事件只记录方法版本、计划ID、版本及目标数量，不记录交接单正文、提示词、凭证、金额、联系人或模型思考过程。原`budget.checked`对实际发给服务商的完整请求计量。

## 修改与续办

例如先向妈妈转400元，给小王的1500元尚未完成：

1. 完成的妈妈转账保留原节点和正式回执。
2. 用户使用经过核实的姓名或唯一别名修改小王的待办金额，按目标ID和版本走原GoalPatch与网关，不重新提交妈妈的转账。
3. 修改使原计划版本递增，旧授权失效，受影响的旧预算等待重新核对。
4. 下一次模型调用即使携带旧金额或伪造的交接单，也以新读取的SQL状态为准。

这里只扩展已有单目标版本化修改的收款人识别；没有将多个修改包装成新的跨业务原子提交机制。整单预检、用户要求的全部满足条件、资金授权与幂等执行仍由原业务层控制。

## 验证与测量边界

专项测试使用真实应用数据库、目标API、授权与回执，以及真实SDK Runner配合合成HTTP响应，覆盖多目标、部分缺项、完成后修改、待核实结果、跨用户／会话隔离、错误回执引用、来源伪造、领域工具并集、角色证据隔离和实际预算请求。

本轮完整离线回归：**954通过、4跳过**（958项，724.31秒），其中新增上下文专项测试23项全部通过；Ruff、两套TypeScript类型检查和`git diff --check`均通过。测试报告保存在本地`.data/context_batch1_full.xml`，业务测试使用隔离沙箱。

本地应用启动后，首页返回HTTP 200，`/health`确认Agents SDK、Supervisor四子角色、Chroma及FastEmbed记忆服务就绪；应用地址为`http://127.0.0.1:8000/`。这项检查未发起资金操作或付费模型调用。

本轮没有运行付费业务模型或MiMo裁判，不能将历史58题冻结分数改称这次上下文改动的效果。真实模型效果需要另建冻结版本、重新执行同题对照；也没有将上下文筛选直接宣称为已经测得的Token或延迟改善。
