# BankFlowBench 三组架构对照方案

本轮使用修订后的 v3 题集，64 题、10 领域、每组 1 轮，共 192 个独立金融沙箱。用于诊断架构差异，不复用旧版修复前后的高分，也不宣称单轮能够代表 All-3 可靠性。

| 组别 | 业务提议 | 研究决策角色 | 证据获取 |
| --- | --- | --- | --- |
| S_AGENT | 统一规则提议器 | 一个通才统一处理账单与理财 | 单轮，提前取得完整证据 |
| M_AGENT | 六领域规则提议器 | 账单与理财角色分工 | 单轮，提前取得完整证据 |
| C（当前） | 六领域规则提议器 | 账单与理财角色分工 | 初始取证、确定性核验、按缺项定向补查，最多配置轮数 |

三组保留共同的 LLM 约束解析器、普通业务规划器、权限网关、资金规则、结构化上下文、记忆策略、核验器和报告渲染器。Single-Agent 指统一的研究决策角色，并不意味着整套应用只有一次模型调用。领域规则模块不是独立 LLM Agent。比较不通过放松安全规则、隐瞒产品条款或取消核验来制造差异。

## 固定条件

- 同一 `deepseek-flash`，推理强度 max，同一单次输出预算，每个任务最多 10 次模型调用。
- 同一 FastEmbed 记忆检索模式，每个任务使用独立账户数据库和会话；题目时钟固定为 2026-10-13 09:00（上海时间）。
- 三组任务随机交错，固定种子 20261017，3 个隔离任务并发；不在测量中修改源代码。
- 冻结题集、预期条件、源代码快照、配置和哈希。失败结果保留，不因分低重跑挑选结果。
- 同一 MiMo 裁判、v4 评分协议；裁判看真实冻结界面结果，包中不包含实验组标签。
- 三组允许同样工具集合，但实际调用次数、Token 和耗时不强行相等，作为成本指标报告。

## 预先指定指标

1. 业务与事实硬检查：状态、授权、资金守恒及可验证事实；不能等同用户目标完成率。
2. 严格规范处理：硬检查通过且本题所有必要语义条件满足。能力边界的正确解释、正确拒绝也可能通过，因此另列用户目标完整兑现和实际办理完成数。
3. LLM-as-Judge：需求覆盖、银行业务正确性、证据推理、可操作性、表达清晰度五维，各维只在适用且有效裁判上计算，显示有效 n。
4. 效率与稳定性：真实模型请求、可观测 Token、整题 P50/P95、错误数、规则回退报告数和研究轮数。缺失用量不视为零。
5. 同题配对：同时报告共同通过、仅左通过、仅右通过、共同失败；只对已决配对给出差值，并公开未决排除数。按场景家族整簇 Bootstrap 95% 区间只作内部诊断。

除全 64 题外，单列脚本包含 `research` 步骤的 6 道预先指定研究任务，避免大量共享普通办理路径稀释研究层差异。不根据结果挑选有利子集。

## 解释边界

现有研究角色主要选择证据工具和已核验结论的重点，数值计算、条件判定与大部分报告文本由确定性模块完成。因此分工可能影响取证、成本与失败率，不保证明显改善最终质量。单轮、6 道显式研究题、自建且开发者使用过的题集，均不足以证明对外泛化或统计显著优势。未引入独立人工标签，不能报告人工一致性或 Cohen's κ。

若发现差异小、当前系统更慢或单轮基线更好，均原样报告；后续改进需另冻版本，不能改写本轮结果。

## 运行与复核

实际运行目录为 `.data/evaluation/architecture64_20261017_v1`。其中保存源代码快照、冻结题目及预期条件、192 个独立任务的状态与模型用量、界面回放、逐题裁判、配对结果。此目录包含内部预期条件，不能作为生产模型上下文，也不应直接公开所有原始记录。

```powershell
.venv\Scripts\python.exe -m evaluation.servicebench run --root .data/evaluation/architecture64_20261017_v1 --variants S_AGENT M_AGENT C --trials 1 --mode llm --memory fastembed --workers 3
.venv\Scripts\python.exe -m evaluation.servicebench capture --root .data/evaluation/architecture64_20261017_v1 --clean-dom
.venv\Scripts\python.exe -m evaluation.servicebench judge --root .data/evaluation/architecture64_20261017_v1 --clean-dom --judge-revision v4 --judge-concurrency 6
.venv\Scripts\python.exe -m evaluation.servicebench report --root .data/evaluation/architecture64_20261017_v1 --clean-dom --judge-revision v4
```

运行必须从新目录开始。同一冻结版本的已完成任务和有效裁判不会被上述命令覆盖。界面回放读取已冻结输出，银行 API 被阻断，回放重试不代表重新办理业务。

基础设施错误最多保存一次独立恢复记录（`--recover-infrastructure`），绑定原始裁判文件哈希；保留原始超时与失败记录。不重评已经有效但分低的答案，也不对结构校验失败的裁判挑选高分。

## 测量诊断补充

执行阶段已经结束、裁判仍在进行时增加一项探索性诊断：若同题在不同组的**完整裁判输入包逐字相同**，直接比较现有有效裁判的必要项结论和五维分数，检查评分波动。只比较完整包相同的记录，不能仅凭回答相似就认定输入相同。不增加裁判请求，不修正任何分数，不用于挑选最优结论；它不属于事先指定的架构主指标。
