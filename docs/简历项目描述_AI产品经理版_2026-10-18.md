# 简行项目：AI产品经理方向简历表述

## 可直接使用的正文

**简行｜银行 AI Agent 与深度研究助手**　[项目展示](https://gist.github.com/xqcd77/b1e1925640af7635176c21ba8bf2fa17)　2026.09–2026.10

针对自然语言办理中重复补充信息、分析与交易衔接不足、受阻后难以续办的问题，面向个人银行用户设计并交付可交互的金融沙箱产品原型。

- **产品定义与MVP：**交付转账、账单、理财等 **6类场景、33项业务入口**，整合自然语言对话、业务卡片与办理进度，覆盖需求提出、计划核对和回执追踪的用户旅程，沉淀场景清单与业务能力边界。
- **版本迭代与方案取舍：**按基础办理、研究增强、可靠性优化三个阶段推进原型迭代，形成 **直接办理＋Deep Research辅助决策** 双路径，新增账单核查、理财比较 **2类研究能力**，支持研究结果经用户选择进入办理。
- **人机协同与风险体验：**明确自动执行、用户确认、强验证 **3级风险授权**，交付资金影响预览、补款续办与人工协助跟踪，区分正常受阻和安全异常，沉淀异常分流与恢复规范。
- **质量验收与产品资产：**历史固定18道可办理任务的严格闭环通过数由 **7/18增至16/18**；建立需求覆盖、业务正确性等 **五维验收标准**，沉淀 **12领域84题场景库、Bad Case分类与版本回归SOP**。

## 事实与指标口径

1. 项目交付为金融沙箱原型，没有真实银行交易或已核实的线上获客、收入、NPS、CSAT数据。
2. 33项为用户可操作的叶子业务入口，不是把43条内部目录/分组记录全部算作独立业务。当前菜单的六类叶子入口分别为8、5、5、7、4、4项。
3. 三个迭代阶段是依据实际工作作的产品化归纳，没有补造V1.0/V2.0等正式发布编号或日期。
4. 54/64→64/64来自历史BankFlowBench v2固定集、同一评分协议下的业务与事实硬检查，不等于全部回答正确率或线上任务完成率。
5. 7/18→16/18来自同一历史固定集中的18道execute＋fulfilled任务。修复前有2题未决，修复后有1题未决，均未计为通过；“严格闭环”还要求全部必需语义项满足。若面试被问及比例，应同时说明这是沙箱开发诊断和已确认通过数。
6. 目前84题为原10领域64题加跨业务资金安排、金融深度研究各10题，共12领域。新的84题三组统一重评尚未完成，正文只使用其资产规模，不声称已经取得总体提升。
7. 五维标准为需求覆盖、银行业务正确性、证据推理、可操作性、清晰度。历史3.35→4.66的需求覆盖均分，其有效样本为52和59，不能改称用户满意度或一次解决率；本版正文不使用该未配对均值作为产品增益主指标。
8. SOP对应现有评测说明的冻结题集、隔离执行、界面回放、必需项验收、失败/未决保留与版本回归流程，不宣称已完成未实际开展的用户访谈、多人团队协同或商业化上线。

## 技术信息转为产品表述的对应关系

| 原技术侧重点 | 产品经理关注的内容 |
|---|---|
| 结构化字段、上下文传递 | 关键信息完整性、多轮一致性、避免重复填写 |
| 共享记忆、检查点恢复 | 会话连续性、任务续办、条件变化后的重新核对 |
| 多Agent、DAG与任务路由 | 任务协同、办理顺序、简单办理与复杂研究的服务分流 |
| Verify / Backtrack / Replan | 异常分流、条件受阻解释、恢复路径与办理可接续性 |
| 权限网关、交易验证 | 人机协同边界、风险分级、资金影响披露与操作授权 |
| 规则校验、LLM-as-Judge | 质量标准、验收门槛、Bad Case归因与版本回归 |

这些是关注点的转换，不是将数据库名直接换成某个产品指标。量化结果仍须与真实测量一致。
