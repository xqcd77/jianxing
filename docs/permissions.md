# 简行权限分级实现与自评

本说明用于检查原型是否按用户身份、Agent职责及操作风险限制访问和执行。自评范围为本地合成金融沙箱；已实现控制支持演示与评审，不构成真实银行安全认证。

## 1 用户身份与资源权限

登录会话确定当前用户。计划、回执、卡片、持仓、历史会话及记忆访问均需核对所有权。demo管理员的演示管理能力不能替其他用户授权金融操作。用户身份从服务端会话取得，不能信任模型输出的user_id或admin字段。

## 2 Agent职责边界

| 角色 | 允许的职责 | 不具备的权限 |
| --- | --- | --- |
| Supervisor | 拆解、分派、补查、汇总 | 直接改账本或批准资金操作 |
| 账单研究 Agent | 读取本人允许范围内的流水和统计证据 | 付款、选品申购、替用户确认 |
| 理财研究 Agent | 读取产品资料与资金约束，提出比较 | 自动填写风险测评或授权申购 |
| 业务办理 Agent | 提交结构化操作草案 | 自签Grant、改变风险等级或绕过网关 |
| 独立核验 Agent | 核查需求、证据、约束与缺项 | 用核验结论代替用户授权 |

## 3 操作风险分级

| 等级 | 执行要求 | 典型情形 |
| --- | --- | --- |
| GREEN | 已登录且属于本人资源，可按规则直接查询 | 允许范围内的只读操作 |
| YELLOW | 展示参数和业务影响，由本人确认 | 普通资金操作、需确认的设置 |
| RED | 核对详情并完成本次强验证 | 大额出金或规则指定的敏感操作 |

当前动态出金按当日累计出金与本次金额合计判断，超过100000分即1000元进入RED。具体操作还受固定级别等规则影响。该阈值只是沙箱设定。产品风险等级另做适当性校验，不能通过强验证绕过产品风险不匹配。

## 4 授权怎样失效

Grant指纹绑定本人、计划版本、节点、操作、对象、金额及风险等级，记录有效期和消费状态。金额、收款人或版本变化后重新核对授权。已完成节点保留回执，继续办理只处理未完成部分；未知提交先查询，停止任务不等于撤销已提交交易。
