# 简行权限分级实现与自评

本文从用户、资源、Agent角色和操作风险四个层面说明权限如何实现，并给出可重复检查的操作步骤。目标是让读者能够判断：谁提出了请求、请求涉及谁的资源、谁可以确认，以及什么情况下服务端必须停止执行。

## 1 权限判断的四个问题

登录只证明当前会话对应某个用户，不能自动开放全部资源。一个角色能提出工具调用，也不表示它可以批准交易。简行将身份、资源访问、角色职责和风险确认分别检查，最终在业务网关汇合。

| 检查层 | 要回答的问题 | 主要判断依据 |
| --- | --- | --- |
| 用户身份 | 请求是否来自有效登录会话 | 服务端Token哈希、有效期、账户状态 |
| 资源所有权 | 计划、卡片、回执、记忆是否属于本人 | 当前用户与资源owner字段，按资源再次核对 |
| 角色能力 | 当前Agent能读取和提出什么 | 服务端角色定义、工具Schema、交接包范围 |
| 操作风险 | 本次业务需要哪种确认 | 操作规则、实时金额、当日累计出金、已验证对象 |

用户ID来自服务端认证结果。客户端传入的user_id、模型生成的admin或verified字段不能提升权限。对无权资源返回拒绝或不存在，避免通过接口顺便暴露他人的业务详情。

## 2 用户与资源访问矩阵

| 资源或动作 | 本人登录用户 | 其他用户或未登录者 |
| --- | --- | --- |
| 查询计划、回执和历史 | 在本人范围内访问 | 拒绝，不返回业务内容 |
| 修改待办目标 | 校验所有权和目标版本 | 拒绝，不能靠知道ID修改 |
| 批准本人敏感业务 | 还须满足风险分级与业务条件 | 不能代为批准 |
| 查询或修改偏好 | 按本人范围、版本和生命周期处理 | 不能通过检索绕过隔离 |
| 配置个人模型Key | 通过本人专用配置接口加密保存 | 不读取、不串用他人Key |
| 演示管理 | 仅演示管理员具备指定管理能力 | 普通账户不能调用管理动作 |

演示管理员的管理权限不扩展为代用户转账的权限。API Key配置响应只说明配置状态；一次性认证器绑定信息只交给已登录本人。部署时仍需保护本机数据文件，接口隔离不能替代操作系统权限。

## 3 Agent之间共享什么、隔离什么

共享的是完成任务所需的结构化事实、结论、来源和缺项，隔离的是无关用户数据、其他角色的原始工作材料以及凭证。共享范围由服务端按用户、会话、任务、角色与来源判断，不由模型自称“协作者”来扩大。

| 角色 | 允许承担的职责 | 不具有的执行权 |
| --- | --- | --- |
| Supervisor | 保留目标、分派、定向补查与汇总 | 直接改账本或替本人批准交易 |
| 账单研究 | 读取允许范围内的流水、统计及相关依据 | 付款、替用户选品或确认 |
| 理财研究 | 比较产品条款、预算与风险限制 | 自动填写风险问卷、授权申购 |
| 业务办理 | 生成结构化操作草案和DAG节点 | 自签Grant、改变规则或绕过网关 |
| 独立核验 | 检查需求覆盖、证据及关键约束 | 把核验通过当成用户授权 |

RoleReturn是受校验的交接包，不是可以自由转发的聊天记录。当前读者规则允许Supervisor和核验角色读取允许范围内的各类角色返回；账单、理财及业务角色分别读取Supervisor和自身角色的返回。用户和任务绑定仍先于角色可读范围。

这使“核验角色需要综合判断”与“专业角色只收到相关内容”可以同时实现。来源发生变化、交接包被改写或角色试图冒用其他用户时应拒绝使用；结构化协议中的authority标识明确其属于建议或只读内容，不是授权。

## 4 三类容易混淆的状态

第一，任务完成与授权完成不同。研究报告完成只说明分析产物已生成，用户选择产品后仍需新的办理检查。第二，确认与适当性不同。验证码正确不能让风险等级2的用户直接购买不匹配的等级3产品。第三，任务停止与交易撤销不同。停止只控制后续执行，已提交交易必须核查真实结果。

这些区分直接影响交互设计：目标卡片应呈现待补条件、待确认、核实中或已完成，并给出对应入口；不能用一个总状态遮蔽多个目标的不同阶段。相关界面仍受已知功能问题影响，不能据此宣称所有表达场景均已完善。

## 5 操作分级与具体边界例子

GREEN允许在本人资源和规则范围内完成部分只读动作；YELLOW要求本人核对参数和业务影响；RED要求本人核对并完成强验证。每个操作的基础级别由bank_rules.py定义，动态出金再依据实时累计金额计算。

| 条件示例 | 应有处理 | 为什么 |
| --- | --- | --- |
| 当日出金为0，本次1000元 | 动态规则下为YELLOW | 阈值判断是“超过1000元”，不是“大于等于” |
| 当日已出金1000元，本次1元 | 刷新为RED，旧确认失效 | 累计出金达到1001元，风险条件已变化 |
| 普通金额但收款对象改变 | 重新核对并授权 | 金额相同不代表同一笔业务 |
| 风险测评与产品不匹配 | 等待更新条件或更换产品 | 身份验证不能绕过适当性检查 |
| 账户处于安全锁定 | 先按规则解锁，再重新核对业务 | 解锁只是恢复办理资格，不是自动批准付款 |

阈值用于合成沙箱。其他操作可有固定分级，不能把所有低于1000元的业务都归为普通确认。

## 6 Grant的生成、消费与失效

Grant可理解为服务端保存的“本人对这一版具体动作的许可”。在用户完成所需确认后生成，默认有效5分钟，绑定用户、节点、授权指纹和风险级别。执行前重新计算指纹，并要求许可未过期、未消费且与当前动作一致。

指纹包含计划及版本、操作、金额等参数、当前风险级别和已解析的收款对象。参数变化、报价更新、计划版本变化或累计风险升级都会使旧指纹不再匹配。修改密码会撤销旧会话和旧授权，避免此前凭证继续有效。

执行成功后记录授权消费与回执。重复点击或恢复任务必须先读取已有状态；不允许把同一个许可重复花在新的资金操作上。对未知提交，系统保留原节点及幂等标识查询结果，不自动再造许可或付款。

例：用户批准“给妈妈400元”后，将金额改为800元。界面即使仍有旧确认按钮，服务端也应拒绝旧指纹，展示新金额并重新确认。安全性由服务端绑定保障，不能仅依赖界面及时刷新。

## 7 自评操作清单

以下步骤在独立合成数据目录、本人测试账户和可验证联系人中执行。每项同时检查响应、授权记录和实际账本，不以提示语是否友好作为唯一标准。

| 检查动作 | 预期结果 | 证据入口 |
| --- | --- | --- |
| 未登录读取账户概览 | 拒绝读取账户数据 | test_safety.py |
| 用户B读取或批准A的计划 | 拒绝，A的资金及授权不变 | 同文件cross_user测试 |
| 草案伪造确认字段 | 非法工具字段被拒绝 | 同文件injection测试 |
| 已确认后修改金额 | 旧指纹失效，要求新确认 | 同文件edit测试 |
| 累计出金跨过阈值 | 普通确认失效并升级验证 | 同文件yellow_boundary测试 |
| 重用已使用验证码 | 拒绝，不增加成功回执 | 同文件mfa_replay测试 |
| 连续3次错误验证 | 敏感操作锁定，解锁另走流程 | 同文件mfa_three_failures测试 |
| 用过期或越权索引命中回读 | 原文层再次拒绝无效访问 | test_chroma_memory.py |
| 两用户配置同厂商模型 | 各使用本人的Key，不交叉泄漏 | test_personal_model_settings.py |
| 完成转账后恢复任务 | 原回执保留，不重复资金写入 | test_lite66_repairs.py |

测试文件均位于tests目录，具体测试函数与输入可直接查阅源码。自动用例中的模拟模型输出用于稳定验证规则，不等同于对所有真实模型行为作出保证。

## 8 当前结论与证据边界

身份与资源检查落在security.py、engine.py及资源服务；角色返回和上下文范围落在role_returns.py、context_builder.py；记忆检索与原文复核落在memory.py及memory_index.py。权限不依赖某一个模型的遵从性，模型不能签发服务端Grant。

当前实现具备本人资源隔离、角色范围、动态操作分级、授权失效及防重复执行控制。2026-10-29离线汇总为1100通过、4跳过，2026-10-28的66题诊断未观察到资金与授权不变量违规。跳过项和未覆盖的攻击面不视为已通过。

自评结论适用于本地合成沙箱。生产身份体系、分布式权限治理、独立渗透和外部审计存证尚待接入。已知风险文档逐项说明剩余问题及关闭条件；本说明不把后续规划写成已实现能力。
