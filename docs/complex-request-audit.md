# 复杂业务、响应速度与任务记忆：排查和修复

日期：2026-10-23。范围：当前 Supervisor 应用入口、Agents SDK Harness、六类业务规则服务、Chroma 共享记忆与网页交互。

## 发现的问题及原因

| 用户看到的问题 | 代码中的原因 | 本轮修改 |
| --- | --- | --- |
| 转账＋ETF＋会员整句被拒绝，或漏掉后面的目标 | 原意图结构以单类银行任务为中心，公开资料与银行任务互斥；旧快捷路径只保存转账和资料两个目标 | 增加独立 `additional_goals`，逐项保留可办理任务、公开查询、能力缺口和待补条件；旧双目标路径遇到第三项操作退出，由完整规划器处理 |
| 4500元本金被当作转给妈妈的金额 | 多个数字缺少动作绑定，金额抽取可能取第一个数字 | 收款对象和转账动词绑定动作金额；总资金、ETF预算、每次定投金额分开存储；明确金额优先于“剩余”等笼统描述 |
| 新卡里的1500元被当作给联系人转账 | 卡片与独立资金账户的语义没有在工具描述和提示词中明确 | 说明卡片共用本人账户，不存在独立充值余额；保留办卡和1500元用途两项，不擅自改成转账、预留或额度修改 |
| 一半的钱转给妈妈进入理财研究 | 相对金额没有确定性处理，路由未完整覆盖“转给”等表达 | 按实时可用余额计算，默认排除预留、预计收入和未结算赎回；形成待确认转账，保留网关验证 |
| 等待很久 | 明确办理也经过模型路由和结构提取，结构任务还启用了长推理；额外资料查询串行等待 | 明确、可完整解析的请求走规则短路径；业务结构提取、路由与独立核验关闭额外长推理；独立公开资料读取并发；保留复杂研究的研究角色 |
| 多轮后遗忘ETF或会员；问进度变成泛泛解释 | 依赖有限聊天窗口，没有独立待处理目标账本；进度请求未始终绑定活动任务 | 持久保存用户/会话下的目标清单；精确补充只更新对应目标；进度从已有计划或研究记录读取 |
| 改转账后，补充会员却使旧ETF预算重新有效 | 目标共用一个计划版本，更新某个目标意外刷新其他目标的版本 | 公开资料目标分别绑定计划版本；未重新核查的预算保持 `NEEDS_RECHECK`；更新时只合并明确修改的目标 |
| ETF公开查询抢先返回，漏掉同句办卡/订会员 | 公开资料入口早于 Supervisor，动作排除不完整 | 在入口识别同句办卡、会员、转给、余额查询等动作，交给多目标办理路径 |

补充口语检查实际发现并修复了两条遗漏：“麻烦办张虚拟银行卡，并把1500块放到这张新卡里面”，以及没有标点的“我的4500元给妈转1200元剩下推荐ETF再开通视频会员”。这两条已作为可重复检查保留。

## 架构、提示词与工具逐层核查

当前仍是五个模型角色，六类领域服务是规则组件，不能把它们计为六个自由执行交易的模型。Agents SDK 负责统一模型提案调用；LangGraph 仍负责原有持久工作流。没有将 Chroma 用作资金账本。

| 层/角色 | 核查内容与处理 |
| --- | --- |
| API与Supervisor | 公开查询、本人入金、进度追问、明确办理、研究的优先级；修复公开查询抢占和比例转账误路由。未知语句必须保留全文进入业务模型 |
| 业务办理Agent | 系统提示词升级为 `banking-planner-v7-goal-coverage`，要求每个原始目标都有去向，区分顶层必要缺项与独立能力缺口，不因会员开通不支持而删除转账 |
| 账单研究Agent | 继续只读取本人授权的账单、现金流和原始证据；本轮明确转账不进入此角色 |
| 理财研究Agent | 继续核对产品、风险、期限与到账条件；真实ETF资料不映射到本地模拟理财，研究和购买授权分开 |
| 独立核验Agent | 输入增加 `additional_goals`，核查原句每个目标的覆盖；资料目标或能力缺口已有明确去向时，不要求生成虚构交易节点 |
| 工具目录 | 增加转账、预留、赎回、卡片申请/限额、订阅查询/取消/提醒等关键操作的业务含义和不可替代关系；`submit_plan`只提交草案 |
| 规则服务、DAG与网关 | 新卡的后续操作引用申请结果，并声明依赖；资金预检、用户确认、强验证、版本指纹、事务与幂等回执保留 |
| 共享记忆 | Chroma检索、TextRank原句提取、SQL原文回读继续使用；任务清单直接读取持久结构化记录，不靠向量相似度猜当前任务 |
| Harness与指标 | 继续记录角色、调用时长、Token、错误代码；完整请求预算与取消传播保持。模型输出无效时有界修复，不能默认放行 |

新的处理顺序：

```text
已认证请求＋原始用户文字
  → 进度/明确目标更新：读取本人会话的真实任务状态
  → 完整、无歧义的明确请求：规则绑定动作、对象、金额、目标
  → 其他请求：完整原文交给业务模型或研究路径
  → 银行任务：规则编译 → 整单预检 → 必要的独立核验 → 待确认计划
  → 附加目标：先持久化 → 公开资料核查 / 缺项说明 / 能力缺口
  → 同一页面显示各项进度；交易须在办理卡片中授权
```

规则路径不是任意文本匹配：条件、预约、假设分析、未解析的连接词或其他动作会退出快捷处理。不能为了减少模型调用而只接受前半句。对“剩余一半”，按同一计划前序转账后的剩余可用资金计算，金额按分向下取整。

## 三个原始反馈现在如何处理

1. **给妈妈500元＋1000元投资ETF＋订会员**：显示三个目标。转账500元等待授权；ETF预算1000元单独核查；会员开通需求保留并明确当前未接入商户开通服务。不会默默丢弃任何一项，也不会买入模拟理财冒充ETF。
2. **申请新卡＋向里面放1500元**：先确认虚拟卡/实体卡，明确类型后生成办卡计划；1500元用途保留。当前卡片共享本人账户，没有独立充值余额。可向用户解释限额或预留的区别，但不能自动替换其请求。
3. **一半的钱转给妈妈**：例如实际可用6000元，生成3000元转账待验证计划。若总余额6000元、已预留1000元，可用5000元，一半为2500元。当前资金不包含预计收入。

## 任务记忆与一致性

- `goal_agenda`按用户与会话保存原始目标、状态和当前关联计划，超过12条聊天历史仍可读取。
- `request_goals`按计划保存页面可展示的目标。银行目标状态以实际节点与回执为准，不能因聊天中的“好了”更新为成功。
- 修改ETF预算仅改ETF目标；选择会员类型仅更新会员目标；已完成转账不重新提出或再次扣款。
- 公开资料目标记录对应的计划版本。修改转账后旧预算标记待核查，补充会员不会清除此标记。
- 用户、会话与计划所有权检查保留；更新一个目标时合并其他最新目标，避免用整份旧清单覆盖不相关更新。
- 查询结果先前保存的原文、来源、金额口径可以回读；检索摘要不授予交易权限。

## 验收与复现

主集：[10道复杂业务题](../evaluation/cases/complex_requests_10.json)。覆盖三目标、指代、比例、冻结/预留资金、顺序计算、总资金与单次投入、跨轮纠正、交易完成后补充、新卡结果依赖、否定与改口。每题验证目标和实际节点、金额、状态、授权前零转账及必要回执，不以模型自评分为通过依据。

补充集：[4道口语变体](../evaluation/cases/complex_paraphrases_4.json)。中文数字、中文百分比、口语化卡片用途、无标点三目标；其中三题实际经过业务模型，检查规则以外的完整提取路径。

本轮联调结果：主集 **10/10**；补充集 **4/4**。使用当前配置的 deepseek-flash、Agents SDK、实际 Chroma 与 fastembed；每题使用全新临时账户与索引。只复用不可变Embedding模型缓存。没有在用户现有账户里模拟转账或改变余额。

## 当前能力边界

ETF查询可核对已接入的官方目录、金额预算与待验证条件，尚未连接证券交易通道，不能声称已买入或开通日定投。商户新会员开通尚未接入。卡片仍共用本人资金账户，未新增卡级资金子账户。这三项若需要真正办理，需要相应产品能力、工具和回执模型，不能靠修改提示词伪装实现。

该测试集用于本项目缺陷回归，题目由本次反馈扩展而来，不是独立盲测或覆盖所有自然语言的保证。完整模型路径仍有外部服务延迟与输出失败的可能，系统保留校验和停止机制。
