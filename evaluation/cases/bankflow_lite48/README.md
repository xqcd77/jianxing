# BankFlowBench-Lite48

版本：`bankflow-lite48-v1-20261018`；编制日期：2026-10-18。

48个完整任务、10个主领域、四档难度。以业务和研究覆盖为依据精编已有84题，保留全部历史数据。
2026-10-19历史冻结结果为44/48（91.67%）、五维加权4.65/5；历史Single-Agent为32/48（66.67%）、3.85/5，调用预算10与16不同，见[历史评测说明](../../../docs/evaluation.md)。当前SDK/Chroma版本另见[58题审计与修复](../../../docs/evaluation58-audit-2026-10-24.md)，不可混称当前成绩。
这是已被项目作者使用过的诊断开发集，未经独立金融专家双标；不是新盲测集。

| 专家 Expert | 8 | 开放方案/反事实综合、动态失效、并发或提交未知等；给出可核验完整结果和边界。 |

四档是任务结构的作者预标注，逐题理由见case_design.jsonl。单独出现强验证、长文本或多个工具不会自动提高难度。
研究题的完整闭环是证据充分的决策结论并遵守只读要求；不能强迫其转账或申购。只有明确要求办理且可办理的题才以真实回执判办结。

预先指定三个子集：基础业务/服务32题，跨业务协作8题，金融深度研究8题。主领域互斥，能力标签允许交叉。
跨业务题不等于必须由多个LLM完成；研究题不等于只要多调用几轮就得高分。

## 参考基准及迁移边界

- [OpenThoughts-TBLite](https://github.com/open-thoughts/OpenThoughts-TBLite)：以Claude Haiku 4.5参考通过率划分Easy>=70%、Medium 40–69%、Hard 10–39%、Extreme<10%；100题，40/26/26/8。迁移：借鉴精简、覆盖与经验校准；本项目Expert是结构标签，不冒称已达到其Extreme参考成功率区间。
- [τ-Knowledge / τ³-Banking](https://taubench.com/blog/tau-knowledge.html)：知识检索、规则应用、受控用户状态变化与可验证最终数据库状态；未采用本项目四档难度分类。迁移：原始证据—规则应用—用户授权—实际状态核验；研究任务按只读答案与不写入核验，执行任务检查实际回执。
- [FinGAIA](https://arxiv.org/html/2507.17186v2)：三级场景：基础业务分析、资产决策支持、战略风险管理；文中分别描述通常<=5步/1–2工具、5–7步/>2工具、约10步/多工具。迁移：借鉴金融任务深度与跨来源综合；工具数量只是参考，不规定必须调用几个Agent或工具。

不能把三份基准说成共同定义了本项目四档。TBLite为经验通过率分档，FinGAIA为三级金融任务深度，τ³-Banking强调检索与可验证业务结果。
可以在独立参考模型上对预先确定的小样本做重复校准，得到成功率和区间；校准仅修订下一版本标签，不按三个对照架构的输赢删题。

## 历史三组定义与当前对照边界

历史S_AGENT是统一研究决策角色，M_AGENT是账单/理财分工的单轮研究，C是分工且可有界补查。
三组普通办理共用主规划器、确定性银行规则与核验器，研究数学和报告大部分亦为确定性程序生成。
因此该题集主要检验研究策略、上下文和组合任务行为，不能仅靠换题证明一般意义的多智能体一定优于单智能体。
Single-Agent仍可使用相同工具和证据；比较质量同时报告调用、Token和耗时，检验专业分工/补查是否值得成本。
保留当前单轮基线首轮获得完整研究证据的实现，不借调整来源可见性制造C的优势。

当前发布采用独立运行的SUPERVISOR组，包含1个Supervisor与4个子Agent，不能将旧C组换名充当当前成绩。与冻结Single-Agent的对比包含业务修复和调用预算变化，不是等预算架构消融。

## 成本

一轮三组48×3=144份判分，对原84×3=252份减少108份（42.86%）。这是最大判分请求数的变化，不是已测得的人民币费用降幅。
保留应用与界面统一流程。不能把API答复判分和界面回放判分混在一起，也不能因省钱把未知直接判通过。
初轮不强制全套重复三次；如要复测稳定性，预先固定少量哨兵题及全部三组，单独报告，不将一次试跑写成All-3。

## 使用方式

在项目根目录使用以下命令；前两条只做本地校验。

```powershell
.\.venv\Scripts\python.exe -m evaluation.servicebench audit --suite lite48
.\.venv\Scripts\python.exe -m pytest tests/test_lite48.py -q
```

当前应用执行、界面回放、MiMo v8判分与离线复算命令见[评测入口](../../README.md)。run与judge分别调用付费业务模型与裁判API，须使用新目录保留历史。

每份回答必须来自真实应用隔离运行与冻结DOM；旧84题成绩不能直接改称本版成绩。
未改题的旧回放如需复用，先核验用户输入、环境、模型配置、程序版本、候选内容和原子验收项均一致，记录来源；更改验收项的新订阅题须新跑或按明确回放版本重评。

## 文件

- public.jsonl：用户脚本；控制器逐条送入，不能将整份脚本或金标预先发送给业务模型。
- private_gold.jsonl：冻结执行契约、原始合成环境、正确结果和评分项，仅控制器/裁判可读。
- case_design.jsonl：逐题难度理由、能力标签、原题ID、修订记录及来源契约哈希。
- 逐题评测卡.md：全部48题的前置条件、完整脚本、正确结果与验收点。
- 覆盖矩阵.md：六类银行业务及外部领域的实际覆盖和剩余缺口。
- selection_audit.json：84题逐题保留/删除原因，含被排除的策略不一致题。
- evaluation_plan.json、评分与节费说明.md：指标、预指定子集、公平性和节费办法。
- manifest.json、file_checksums.json：题集统计与文件哈希。
