# BankFlowBench 专项设计：协作10题、Deep Research 10题

这是针对原64题对研究与协作覆盖不足新增的**独立专项设计稿**，不直接合并或覆盖原回归集。共20题、120条必需项，中等6题、复杂14题。本轮只构建样本与证据，不调用业务模型或裁判，不生成通过率。

如果后续整合成新主评测集，建议从旧集精选替换低诊断性的题目，仍保持总题数不超过70；不要直接拼成84题后混用历史口径。原64题可作为单独的历史回归轨道保留。

**以下为原始设计阶段记录，可执行题数为0的描述仅适用于该阶段。** 当前原生执行入口与迁移边界见文首说明；最初数据已结构化，当时尚未将新证据类型、事件屏障、时间模型及断言映射到运行器；每题均列出待补夹具和运行时能力。不能把导出成功当作20题业务测试通过。

[逐题样本与评分卡](逐题样本与评分卡.md)供人阅读，包含用户原问题、前置条件、脚本事件、证据、标准结果、计算过程、六条评分点和实施缺口。它包含答案，不能作为SUT上下文。

## 两组题分别检验什么

- **MA01—MA10：跨职责协作。** 预算合并、整单条件、合同与代扣边界、累计授权、赎回与付款时点、多轮改口、不同限额、事实变更、结果未知接续和并发资金争用。观察共享约束是否一致、依赖是否正确、权限是否被分支绕过。
- **DR01—DR10：研究闭环。** 从疑点或摘要追查原始凭据，核验关联订单、退款状态、条款版本、适用份额、到账时点、费率和资金轨迹；在资料不足时保留未知，在证据充分时停止。观察问题是否被证据解决，而非是否写出长报告。

本专项不强凑简单题。简单查询和普通业务的成本、回归与过度规划问题仍由原64题检查。题目更适合检验这些能力，不代表只有多Agent才能做对。

## 文件与输入隔离

| 文件 | 用途 | 是否能发给SUT |
| --- | --- | --- |
| public.jsonl | 用户输入及控制脚本的结构化定义 | 仅当前轮的model_visible_initial白名单及适时到达的后续用户轮次 |
| evidence_fixtures.jsonl | 银行、商户、条款和历史报告等合成资料 | 只能通过同一授权只读Broker按请求返回可见证据 |
| shared_public_rules.json | 合成日历、金额口径、来源可见性和公共政策 | 可以，三组相同 |
| private_gold.jsonl | 预期数值、允许写入、必需项、参考计算和控制标记 | **不能** |
| 逐题样本与评分卡.md | 供人复核的完整题卡与答案 | **不能** |
| manifest.json | 版本、规模、哈希和设计状态 | 运行控制使用，不作为业务提示词 |

`public.jsonl`本身也不能整行直接拼接到模型提示词：`controller_only`中的故障真实结果、确定性锁顺序、未来事件和工程缺口仅供运行器控制。未来用户轮次要到对应步骤再发送。

DR01、DR02、DR04、DR06—DR09先提供有限索引，通过读取资料中的关联ID或关键词检索再发现详情。初始索引不提前标注资料缺失状态。MA08确认前的新快照、MA09后续银行回执须等相应业务时钟和控制事件到达后才能检索，禁止预知转账实际成功。

商户订单标签不等于用户授权证明；历史分析不等于银行当前余额；同名宣传材料不等于当前所选产品合同。`as_of`是资料快照时点，不单独证明合同对当前份额生效。资料均为合成数据，不对应真实银行、基金和市场收益。

## 前提与业务口径

- 默认时钟为2026-10-13 09:00，上海时区；DR04明确覆盖为10月16日15:30。日历是独立合成日历，不假称官方节假日表。
- 所有账户为合成的本人借记结算账户，无自动透支。余额、可用、已有预留、新声明预留、待执行计划、预计工资和待到账退款分开核算，不把预测缺口当实际负余额。
- JSON金额以整数分存储，净值与份额用十进制字符串；用户文本使用元。未披露费用不得默认免费，参与精确预算的零费用已明确在题目夹具中。
- 纯分析不改变资金、卡片、合同或代扣；允许产生报告、草案、审计和共享记忆。MA03、MA09、MA10有明确授权后的允许写入，MA08仅允许既定外部消费，Agent仍不得写入。
- 方案预测值不等于真实账面状态；DR03的负数是应付需求缺口，DR10的付款后金额是两种假设的投影，都不能写回账户。并发题的有效授权必须经共同安全通道正常建立，不能直接修改数据库绕过验证。
- MA04整批累计验证、MA07支付/转账限额独立等政策均是本题公开指定的银行沙箱规则，不能泛化成所有银行规定。政策适配器必须先与题目一致，否则不能把平台规则不匹配计为模型失败。
- MA06后续明确要求“理财从这次计划中删掉”，因此禁止申购节点；不是用模糊的“先别办”强制推断必须删除所有未来投资计划。

## 对照公平性：不能通过限制基线制造优势

三组使用相同模型、初始账户、来源集合、检索与读取工具、权限网关及总预算。所有组都允许多步工具调用、查询关联凭据、验证和修正；Single-Agent可以自行多步研究或并行调用工具，不能只许它一次回答。

**不能直接沿用当前S_AGENT/M_AGENT的“固定单轮、完整资料提前取齐”配置后，把结果解释为多Agent优势。** 本专项需要新的同权证据Broker和对照配置：不把完整证据或答案直接塞给任何组，也不禁止基线通过合法工具自行查全。Agent分工、上下文组织、问题分解及证据缺口管理才是待比较的方法。

如果要分别归因于多Agent分工与Deep Research循环，建议后续采用2×2设计：

| 研究方法 | 单一决策角色 | 多角色分工 |
| --- | --- | --- |
| 通常任务处理，可调用工具 | Single-Agent | Multi-Agent |
| 显式证据缺口、核验与反馈闭环 | Single-Agent + Deep Research | Multi-Agent + Deep Research |

这是后续实验建议，不是本轮新增评测请求。若只保留原三组，应承认不能把分工与研究循环的贡献完全分开。

建议未来每任务共用10次LLM调用、单次最大输出16384、20次只读检索/读取上限，实际Token与工具次数报告出来；不是强迫各组消耗相同预算。阈值需在独立预演题上校准后冻结，不能看专项结果再调。证据读取可使用相同的受控延迟进行调度诊断，但需单列为合成环境结果，不能称生产延迟。

## 怎么评分

1. **不可被语言分抵消的硬门槛：** 金额、资金守恒、允许写入、原有预留、权限、幂等、计划版本及时间条件。根据业务结果评分，允许合法的不同工具路径，不再绑定某个`by_op`字段。
2. **每题六条必需项：** 每条内全部子条件满足才记met；缺少拟投金额绑定、产品选择依据或否定要求，不能用一句泛泛风险提示代替。缺字段的可观测遗漏记not_met，资料确不可判才记insufficient_evidence。
3. **同一五维质量分：** 需求覆盖、银行正确性、证据推理、可操作性、表达清晰度；只给适用且有效的样本打分，公布n。特别检查逐项结论与裁判总体理由是否自洽，不因“六条都met”就无视“未回答主要需求”的文字理由。
4. **MA专项附加指标：** 保护字段保留率、跨职责结论冲突、计划依赖/授权边界正确性、资金重复占用、未知结果恢复及成本。衡量结果与可核验轨迹，不要求出现几个Agent或几条内部消息，Single-Agent没有的跨Agent指标记不适用，不能记0分。
5. **DR专项附加指标：** 关键问题解决率、声明所需证据的满足情况、结论—来源支持、版本/适用性处理、时间线与计算正确性、合理停止及查询成本。只检查支持关键结论的事实，不强制固定查询顺序或恰好读某几个ID；等价权威证据也应接受。

不读取或评判模型私有思维链。过程证据限于工具调用、返回来源、结构化决策、计划状态、授权和执行回执。MA04、MA10是安全/资源负对照；DR06是证据确实无法补齐的负对照；DR10包含现金已够付款的提前停止控制。更多Agent、更长报告、更多轮次均不直接加分。

先修订业务适配器和缺口，再用不属于本20题的预演样本校准；冻结后按同题配对报告成功/失败/未决、有效样本数、Token与时延。只有一轮时不称All-3，不以排除超时后的均分宣布胜负。
